# Proxmox Backup Script — бэкап ВМ и LXC-контейнеров Proxmox на локальную машину

Скрипт запускается на вашей рабочей машине (или выделенном сервере бэкапов)
и автоматизирует цикл резервного копирования гостей ноды Proxmox VE.

**Только стандартная библиотека Python** — ничего доустанавливать не нужно
ни на рабочей машине, ни на ноде.
```

## Как это работает

1. По SSH получает список гостей: `qm list` (ВМ) + `pct list` (LXC,
   включая записи с «-» в столбце Lock — блокировки нет).
2. Показывает хранилища со свободным местом (`pvesm status`, столбец
   Available разбирается по заголовку таблицы, а не по позиции; если
   столбца Available нет или значение не читается — свободное место
   показывается как «неизвестно», а не как 0).
3. Проверяет, что уже лежит в выбранном хранилище ноды (`pvesm list`):
   если там есть резервные копии, созданные ранее, сообщает об этом;
   в живом терминале печатает их нумерованный список и предлагает выбрать
   копии для скачивания (см. «Скачивание уже имеющихся копий»).
4. Формирует целевой список: из конфига (`include`/`exclude`) или
   интерактивно (`--interactive`).
5. Запускает на ноде `vzdump` (режим snapshot/suspend/stop, хранилище —
   из конфига или выбрано интерактивно).
6. Считает SHA256 архива на сервере.
7. Копирует архив по сети (`scp`) в каталог запуска — сначала во временный
   файл `.tmp_*`, затем переименовывает.
8. Считает SHA256 локально и сравнивает с серверной суммой, затем проверяет
   структуру архива (сигнатуры форматов vzdump — см. «Проверка целостности»).
9. С существующими локальными копиями осторожен: файл с тем же именем
   **никогда не перезаписывается**. Если локальная копия уже есть и
   идентична новому архиву — скачивание пропускается; если отличается —
   новая копия сохраняется рядом под именем `*_dupN`.
10. Если все проверки пройдены и `BACKUP["delete_after_download"] = True`
    (по умолчанию) — удаляет архив и служебные файлы (`.log`, `.notes`)
    с сервера и проверяет, что удаление действительно прошло; ошибка
    удаления не замалчивается, а попадает в лог и сводку. Если выключено —
    архив остаётся на ноде.
    При провале любой проверки — временный файл удаляется, архив на сервере
    **остаётся**, гость помечается как ошибочный.
11. Печатает сводку и пишет лог `logs/backup_ГГГГММДД.log`.

Хранилища Proxmox Backup Server (тип `pbs`) распознаются автоматически
и обслуживаются отдельным механизмом (см. «Proxmox Backup Server»).

**Локальные копии никогда не удаляются автоматически** — старые бэкапы
в папке назначения остаются, очистку делайте вручную.

## Требования

- Локальная машина: Python 3.8+ и утилиты `ssh`/`scp` в PATH (пакет
  openssh-client). Больше ничего.
- На ноде Proxmox ничего ставить не нужно (для скачивания из PBS —
  `proxmox-backup-client`, см. раздел про PBS).

## Подключение по SSH

Скрипт поддерживает два способа аутентификации:

### Вход по ключу (рекомендуется)

```bash
ssh-keygen -t ed25519            # если ключа ещё нет
ssh-copy-id root@192.168.1.10    # скопировать ключ на ноду
ssh root@192.168.1.10 'qm list'  # проверка: вход должен быть без пароля
```

В конфиге оставьте `password: ""`. При первом подключении отпечаток хоста
принимается автоматически (`StrictHostKeyChecking=accept-new`).

### Вход по паролю

Два варианта:

1. **`--ask-pass`** (рекомендуется) — скрипт спросит пароль в терминале
   перед началом работы. Пароль не сохраняется нигде.
   ```bash
   ./proxmox_backup.py --ask-pass
   ```
2. **Пароль в конфиге** — задайте `PROXMOX["password"]` в
   `backup_config.py`. Пароль хранится в открытом виде — защитите файл:
   `chmod 600 backup_config.py`.

Технически ввод пароля выполняется через псевдо-терминал (модуль `pty`):
скрипт сам отвечает на запрос ssh, поэтому работает и в сценариях.
Если ssh запросит пароль повторно (неверный пароль), скрипт завершится
с понятной ошибкой.

## Конфигурация — backup_config.py

Конфиг — обычный Python-файл, исполняемый программой. Поиск: `--config`,
затем `./backup_config.py`, затем рядом с кодом проекта (в каталоге
`proxmox_backup/`).

```python
PROXMOX = {
    "host": "192.168.1.10",   # IP или FQDN ноды
    "port": 22,               # SSH-порт
    "user": "root",           # SSH-пользователь
    "key_file": "",           # приватный ключ; пусто = ~/.ssh/id_*
    "password": "",           # SSH-пароль (лучше --ask-pass); пусто = вход по ключу
    "ssh_timeout": 0,         # лимит тишины сессии, сек (0 = без ограничения)
}
BACKUP = {
    "storage": "local",       # хранилище Proxmox для транзитных архивов vzdump
    "mode": "snapshot",       # snapshot | suspend | stop
    "compress": "zstd",       # zstd | gzip | lzo | none
    "destination": "./backups",  # локальный каталог копий
    "delete_after_download": True,
                              # True  — удалять архив на ноде после успешной проверки;
                              # False — оставлять архивы на ноде;
                              # разово перекрывается флагом --keep-on-server
}
VMS = {
    "include": [],            # только эти ВМ/контейнеры, напр. [100, 101, 200]
    "exclude": [],            # все, кроме этих (если include пуст)
}
LOGGING = {
    "dir": "./logs",          # каталог логов
    "console_level": "INFO",  # детальность в консоли
    "file_level": "DEBUG",    # детальность в файле
}
```

## Параметры командной строки

| Флаг                   | Описание                                                            |
|------------------------|---------------------------------------------------------------------|
| `-c, --config FILE`    | Путь к Python-конфигу                                               |
| `-i, --interactive`    | Интерактивный выбор гостей, хранилища и режима                      |
| `--include VMID…`      | Бэкапить только перечисленных; перекрывает `VMS["include"]`         |
| `--exclude VMID…`      | Исключить перечисленных; перекрывает `VMS["exclude"]`               |
| `--mode MODE`          | `snapshot` / `suspend` / `stop`; перекрывает конфиг                 |
| `--storage NAME`       | Хранилище на ноде; перекрывает конфиг                               |
| `-d, --dest DIR`       | Локальный каталог назначения; перекрывает конфиг                    |
| `--ask-pass`           | Спросить SSH-пароль в терминале                                     |
| `--keep-on-server`     | Не удалять архив на ноде после проверки; перекрывает конфиг         |
| `--list-backups`       | Показать копии, уже лежащие в хранилище ноды, и выйти (без бэкапа)  |
| `--download-existing`  | Скачивание уже имеющихся копий по номерам; без бэкапа гостей        |
| `--log-level LVL`      | `DEBUG` / `INFO` / `WARNING` для консоли                            |

В флагах `--include` / `--exclude` допустимы запятые и несколько значений:
`--include 100,101` или `--include 100 101`.

## Интерактивный режим

```bash
./proxmox_backup.py -i
```

Скрипт покажет всех гостей (ВМ и контейнеры), спросит, кого бэкапить
(все / выбранные ID / все кроме ID / списки из конфига), покажет хранилища
со свободным местом, предложит режим бэкапа и подтвердит запуск.
Там, где вы просто нажимаете Enter, берутся значения из конфига —
списки из ключей CLI (`--include` и т.п.) тоже учитываются.

PBS-хранилище выбрать для vzdump нельзя — скрипт отклонит выбор
с объяснением и попросит файловое хранилище.

## Скачивание уже имеющихся копий

Перед созданием новых архивов скрипт проверяет выбранное хранилище ноды
(`pvesm list <storage> --content backup`). Если там уже есть резервные
копии — от прошлых запусков скрипта, заданий Proxmox или сделанные
вручную — скрипт сообщает об этом (количество, суммарный объём), а при
живом терминале печатает нумерованный список и предлагает выбрать копии
для скачивания:

```
Найденные резервные копии:

[1] local:backup/vzdump-qemu-100-2026_10_30-02_00_00.vma.zst (3.2 ГБ, ...)
[2] local:backup/vzdump-lxc-101-2026_10_30-02_10_00.tar.zst (1.1 ГБ, ...)

Выберите резервные копии для скачивания
(номера через запятую, например 1,3,4; Enter — пропустить):

>
```

Правила выбора — как при выборе VMID:

- можно указать одну или несколько копий: `1`, `1,3,4`;
- пустой ввод (Enter) — отказ от скачивания, бэкап продолжается как обычно;
- некорректный ввод (не число, номер вне списка) — понятное сообщение
  и повторный запрос;
- повторно указанный номер учитывается один раз (с предупреждением).

Скачивание выбранных копий идёт тем же конвейером, что и бэкап: путь
архива определяется через `pvesm path`, затем scp, SHA256 сервера и
локально, проверка структуры архива, защита от перезаписи локальных
файлов (`__dupN`), и удаление архива с ноды после успешных проверок —
в соответствии с `delete_after_download` / `--keep-on-server`.
При любой ошибке скачивания локальный временный файл удаляется,
архив на сервере **сохраняется**.

Скачать копии, не запуская бэкап гостей, можно отдельной командой:

```bash
./proxmox_backup.py --download-existing
```

Она печатает тот же нумерованный список, спрашивает выбор и завершается:
код 0 — всё скачано (или нечего было качать), 1 — были ошибки скачивания,
2 — ошибка конфигурации/подключения или закрытый STDIN. Команда требует
интерактивного ввода; в cron её использовать не стоит.

Посмотреть список, не скачивая ничего:

```bash
./proxmox_backup.py --list-backups
```

Сбой проверки (`pvesm list` не выполнился) не останавливает бэкап —
в лог попадает предупреждение, а бэкап продолжается как обычно.

## Proxmox Backup Server (PBS)

Хранилище PBS определяется автоматически по типу из `pvesm status`
(тип `pbs`) и никогда не обрабатывается как файловое:

- **Список снапшотов**: `--list-backups` и интерактивный список работают
  (volid вида `pbs:backup/vm/105/2025-12-31T22:00:00Z`).
- **Выбор и скачивание**: те же нумерованные списки и выбор номерами.
- **Механизм скачивания**: PBS-снапшот — не файл `.vma.zst`, а чанковые
  индексы (fidx/didx), поэтому scp к нему неприменим. Скрипт вызывает
  на ноде `proxmox-backup-client`: восстанавливает все архивы выбранного
  снапшота во временный каталог на ноде, упаковывает в tar, копирует tar
  по scp и проверяет (SHA256 + структура).
- **Результат** — `pbs-vm-105-2025-12-31T22-00-00Z.tar`: tar с
  восстановленными файлами снапшота (raw-образы дисков, конфиг гостя,
  распакованные pxar), а **не** архив vzdump. Для восстановления гостя
  из такого tar используйте ручную процедуру (импорт raw-образа +
  конфига), либо восстанавливайте из PBS штатно (`qmrestore`/`pct restore`
  или proxmox-backup-client).
- **Снапшоты PBS не удаляются никогда** — `delete_after_download` к PBS
  не применяется: жизненным циклом копий PBS управляют prune/GC на
  сервере PBS, а автоматическое удаление снапшота могло бы разрушить
  цепочку инкрементальных копий.
- **Требования на ноде**: утилита `proxmox-backup-client`. Если её нет,
  скрипт выдаёт инструкцию:
  ```bash
  apt update && apt install proxmox-backup-client
  ```
- **Аутентификация**: параметры хранилища (server, datastore, username,
  namespace, fingerprint) берутся из `/etc/pve/storage.cfg` на ноде;
  пароль — из строки `password` в storage.cfg либо из
  `/etc/pve/priv/storage/<имя>.pw` (создаётся при добавлении хранилища
  через GUI/API).
- **Безопасная передача пароля**: пароль PBS никогда не попадает
  в командные строки, DEBUG-лог, сообщения об ошибках и исключения.
  Он читается непосредственно на ноде из тех же источников, что и выше,
  во временный файл (случайное имя, права 600, каталог /dev/shm — tmpfs,
  иначе /tmp) и передаётся клиенту штатным механизмом
  `PBS_PASSWORD_FILE`; файл создаётся уже внутри защищённого блока и
  удаляется после операции при любом исходе — в том числе при ошибке,
  возникшей сразу после его создания. Если временный файл создать
  невозможно, операция прерывается с понятной ошибкой — без перехода
  к небезопасной передаче пароля через командную строку. Механизм
  `PBS_PASSWORD_FILE` поддерживается proxmox-backup-client начиная
  с версии 2.x (в поставке PVE 7+).
- **Надёжная очистка временных файлов**: временный каталог восстановления,
  tar-архив и файл пароля удаляются с ноды при любом завершении операции
  (успех или ошибка), причём удаление подтверждается проверкой фактического
  отсутствия файлов. Ошибка очистки (например, нода стала недоступна сразу
  после сбоя скачивания) никогда не подменяет первоначальную ошибку —
  в лог пишется предупреждение с перечнем путей и явным указанием, что
  временные файлы могли остаться на узле Proxmox (файл пароля — в
  /dev/shm или /tmp, имя вида `pbs-pw.*`; служебный каталог —
  `/tmp/pve-pbs-*`); их стоит удалить вручную при восстановлении связи.
- **Шифрование (encryption-key)**: если для хранилища в storage.cfg
  задан `encryption-key`, скрипт требует файл ключа
  `/etc/pve/priv/storage/<имя>.enc` (там его размещает PVE при включении
  шифрования) и передаёт его клиенту штатным параметром `--keyfile`.
  Ключ не копируется в локальный каталог и не попадает в логи
  (логируется только путь). Перед скачиванием файл ключа проверяется
  на существование, обычный файл, читаемость и непустоту (эквивалент
  `test -f`, `test -r`, `test -s`): если шифрование настроено, а ключ
  отсутствует, не является обычным файлом, не читается или пуст —
  скачивание не начинается, снапшот PBS не изменяется, выдаётся понятная
  ошибка с указанием хранилища и ожидаемого пути к ключу. Наличие файла
  `.enc` само по себе шифрованием не считается — ориентир именно
  параметр `encryption-key` в конфигурации хранилища. Содержимое ключа
  не анализируется и не преобразовывается: неподдерживаемый формат
  ключа (например, ключ с паролем/kdf — они не поддерживаются и в GUI
  PVE) даёт ошибку от самого proxmox-backup-client.
- **Ограничение**: vzdump в PBS-хранилище этим скриптом не поддерживается —
  при выборе такого хранилища для бэкапа скрипт объясняет это и
  останавливается (код 2).

> ⚠️ Поддержка PBS реализована по официальной документации
> proxmox-backup-client и проверена только на эмуляции в тестах
> (см. «Тесты»): юнит-тесты на моках и сквозные тесты на подменных
> ssh/scp. На реальном сервере PBS функциональность не проверялась — перед
> рабочим использованием выполните пробное скачивание одного снапшота.
> То же относится к зашифрованному PBS-хранилищу: в тестах эмулировались
> чтение ключа `/etc/pve/priv/storage/<имя>.enc`, передача `--keyfile`
> клиенту и ошибки при отсутствии/нечитаемости/некорректности/пустоте
> ключа; реальное расшифрование данных не проверялось. Надёжная очистка
> временных файлов (подтверждение удаления, недоступность ноды во время
> очистки) проверена юнит-тестами и эмуляцией; на реальной ноде
> SSH-сбой именно во время очистки не воспроизводился.

## Примеры запуска

```bash
# Всё по конфигу (все гости ноды минус VMS["exclude"]):
./proxmox_backup.py

# Интерактивно:
./proxmox_backup.py -i

# Только две ВМ, с остановкой:
./proxmox_backup.py --include 100 101 --mode stop

# Все, кроме 102 и 105, в отдельный каталог:
./proxmox_backup.py --exclude 102,105 --dest /mnt/nas/pve-monthly

# С запросом пароля SSH:
./proxmox_backup.py --ask-pass

# Показать, что уже лежит в хранилище ноды (без бэкапа):
./proxmox_backup.py --list-backups

# Скачать выбранные имеющиеся копии (без бэкапа гостей):
./proxmox_backup.py --download-existing
```

## Проверка целостности

Копия считается принятой только после проверок:

1. **SHA256 на ноде и локально** — гарантирует, что файл при передаче
   не исказился ни на один байт.
2. **Структура архива** — скрипт проверяет, что скачанный файл действительно
   похож на архив нужного формата: сигнатура `VMA` для `.vma`,
   читаемость tar для `.tar`, разбор gzip-потока для `.vma.gz`/`.tar.gz`,
   сигнатуры потоков для `.zst`/`.lzo` (стандартная библиотека Python не
   умеет распаковывать zstd/lzo, поэтому для них проверяется только
   сигнатура). Это относится и к скачанным старым копиям, и к tar-архивам
   снапшотов PBS.
3. Любая из проверок не прошла — локальная копия удаляется (не трогаются
   только файлы, существовавшие до запуска), архив на ноде **сохраняется**,
   гость/копия помечается как ошибочный.

Ни SHA256, ни проверка сигнатур не гарантируют восстановимость гостя
(например, при битом диске на ноде). Окончательная гарантия — периодическое
**тестовое восстановление** хотя бы самых важных гостей в изолированную
среду (у тестового восстановления VM: `qmrestore` / import в PBS,
контейнеров: `pct restore` в тестовый CTID).

## Удаление архива на сервере

- По умолчанию (`delete_after_download: True`) архив с ноды удаляется только
  после успешных проверок, причём скрипт убеждается, что `rm` реально
  прошёл: при ошибке удаления в лог и сводку попадает предупреждение
  «архив НЕ удалён с сервера», а код возврата остаётся успешным — бэкап
  ведь состоялся. Это относится и к свежим архивам, и к скачанным старым
  копиям.
- `delete_after_download: False` — архивы всегда остаются на ноде
  (транзитные копии придётся чистить вручную).
- Разовый запуск без удаления: `./proxmox_backup.py --keep-on-server`.
- Для PBS-снапшотов удаление не применяется никогда (см. раздел про PBS).

## Тесты

В каталоге `tests/` — два набора тестов на стандартной библиотеке
(`unittest`, без pip-пакетов):

- `tests/test_unit_fixes.py` — 32 юнит-теста на моках (без сети):
  очистка временных файлов PBS при успехе и при каждой из ошибок
  (restore/tar/scp/SHA256, недоступность ноды во время очистки,
  сбой сразу после создания файла пароля), подтверждение удаления,
  проверка ключа шифрования (`test -f/-r/-s`), разбор `pvesm status`
  (Available по заголовку, «неизвестно» вместо 0, резервный разбор),
  регресс отображения LXC («-» в Lock не попадает в имя). После
  реструктуризации патчи применяются к модулям, где функции определены
  (storage.pbs, storage.discovery, proxmox.guests, transfer.verify);
  сами проверки не менялись.
- `tests/test_e2e_emulation.py` — 15 сквозных тестов на эмуляции ноды
  (подменные `ssh`/`scp` из `tests/fakepve/` обслуживают все команды):
  полный конвейер vzdump (6 гостей, ВМ+LXC, удаление с сервера),
  скачивание PBS-снапшотов без шифрования и с шифрованием (`--keyfile`
  во всех вызовах клиента), отказ до скачивания при отсутствующем/
  пустом/нечитаемом/не-файле ключе, очистка временных файлов ноды
  при ошибках restore/tar/scp, отсутствие паролей и содержимого ключей
  в логах, «неизвестное» свободное место без столбца Available.

Запуск всех тестов из каталога проекта:

```bash
python3 -m unittest discover -s tests -v
```

или по отдельности:

```bash
python3 tests/test_unit_fixes.py
python3 tests/test_e2e_emulation.py
```

Сеть тестам не нужна: «нода» эмулируется временным каталогом
(`tests/fakepve/`); временный файл пароля PBS создаётся по-настоящему
(в /dev/shm или /tmp тестовой машины) — именно так проверяются и его
использование, и последующая уборка.

## Коды возврата

| Код | Значение                                        |
|-----|-------------------------------------------------|
| 0   | Все гости успешно забэкаплены и проверены       |
| 1   | Есть ошибки по одному или нескольким гостям/копиям |
| 2   | Ошибка конфигурации, SSH или ноды               |
| 130 | Прервано пользователем (Ctrl+C)                 |

## Автоматизация по cron

```cron
# Ежедневно в 02:00 (вход по ключу):
0 2 * * * cd /opt/pve-backup && /usr/bin/python3 proxmox_backup.py >> logs/cron.log 2>&1
```

`--download-existing` — интерактивная команда, в cron её использовать
не стоит (STDIN закрыт → код 2).

## Ограничения и заметки

- **Одна нода за запуск.** Скрипт работает с одной нодой (список гостей —
  `qm list`/`pct list` именно её). Это нормально для одиночной ноды.
  Если у вас **кластер**, запустите скрипт для каждой ноды отдельно
  (свой конфиг/каталог назначения через `--config`/`--dest`): гости
  живут на конкретных нодах, и один прогон «по кластеру» скрипту не нужен.
- **Локальные копии не ротируются**: все старые архивы остаются в каталоге
  назначения и никогда не перезаписываются (при совпадении имён новая
  копия получает суффикс `__dupN`). Очистку по возрасту/количеству делайте
  вручную или внешним скриптом.
- **Свободное место не проверяется**: на ноде должно хватать места в
  хранилище под самый большой архив, локально — под все копии. При
  скачивании PBS-снапшота на ноде дополнительно нужен объём под
  восстановленные файлы снапшота и tar (примерно размер снапшота × 2).
- **PBS не проверен на реальном сервере** — реализация по документации
  (см. раздел про PBS). Это касается и безопасной передачи пароля
  (`PBS_PASSWORD_FILE`, proxmox-backup-client 2.x+), и зашифрованных
  хранилищ (`--keyfile`): на эмуляции всё проверено, на реальном PBS
  перед промышленным использованием выполните пробное скачивание.
- **Режим `snapshot`** работает «на лету» для дисков qcow2/raw и на
  LVM-thin/ZFS; на обычном LVM vzdump сам откатится к suspend.
- **Режим `stop`** останавливает гостя на время бэкапа и запускает обратно.
- При прерывании скрипта (Ctrl+C) vzdump на ноде может остаться
  недописанным — проверьте `/var/lib/vz/dump` и удалите мусор. Недокачанные
  локальные `.tmp_*` файлы старше суток скрипт удаляет сам при старте.
- Бэкап выполняется **последовательно**, гость за гостем: это щадит сеть
  и диск.
- Если локальный каталог и хранилище `local` на одном диске — места
  потребуется примерно вдвое больше размера архива.
